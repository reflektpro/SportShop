# Product Backlog — проект «СпортТовары»

Список требований к продукту (Product Backlog). Истории упорядочены по приоритету.
Шкала Story Points: 1 — очень просто, 2 — просто, 3 — средне, 5 — сложно, 8 — очень сложно.

---

### US-1. Товары с низким остатком
**Как** менеджер магазина, **я хочу** видеть список товаров с низким остатком, **чтобы** вовремя заказать новую партию.
**Критерии приёмки:**
- Отображаются товары, у которых суммарное количество ≤ 3.
- Список отсортирован по возрастанию количества.
- Если таких товаров нет — выводится сообщение «Нет товаров с низким остатком».
**Оценка:** 3 story points
**Приоритет:** Высокий

### US-2. Поиск по названию и бренду
**Как** менеджер, **я хочу** искать товары по названию и бренду с фильтрами по категории и цене, **чтобы** быстро находить нужные позиции в каталоге.
**Критерии приёмки:**
- Поиск нечувствителен к регистру.
- Можно указать категорию, минимальную и максимальную цену.
- При отсутствии совпадений возвращается пустой список.
**Оценка:** 5 story points
**Приоритет:** Высокий

### US-3. Аналитика по категориям
**Как** менеджер, **я хочу** видеть количество товаров по категориям, **чтобы** понимать структуру склада.
**Критерии приёмки:**
- Функция возвращает словарь `{категория: суммарное количество}`.
- Учитываются все товары каталога.
- Пустой каталог даёт пустой словарь.
**Оценка:** 5 story points
**Приоритет:** Средний

### US-4. Оформление заказа в JSON
**Как** менеджер, **я хочу** оформлять заказ и сохранять его в JSON, **чтобы** фиксировать продажи и передавать данные в учёт.
**Критерии приёмки:**
- При оформлении уменьшается остаток товара.
- Заказ содержит id, название, количество, цену и сумму.
- Заказы сохраняются в файл `orders.json` в кодировке UTF-8.
- При нехватке товара выдаётся понятная ошибка.
**Оценка:** 8 story points
**Приоритет:** Высокий

### US-5. Журнал действий
**Как** менеджер, **я хочу** видеть журнал действий системы, **чтобы** разбирать спорные операции и ошибки.
**Критерии приёмки:**
- Логируются поиск, оформление заказа и сохранение файла.
- Записи содержат дату/время и тип действия.
- Журнал можно вывести в консоль.
**Оценка:** 3 story points
**Приоритет:** Средний

### US-6. Подсветка низкого остатка в меню
**Как** менеджер, **я хочу** получать готовый текстовый отчёт о низком остатке из консольного меню, **чтобы** не собирать данные вручную.
**Критерии приёмки:**
- Функция `highlight_low_stock` возвращает многострочный текст.
- Использует `get_low_stock` внутри.
- Сообщение при пустом результате соответствует критериям US-1.
**Оценка:** 2 story points
**Приоритет:** Высокий

### US-7. Импорт каталога из CSV
**Как** администратор, **я хочу** загружать каталог из CSV-файла, **чтобы** обновлять ассортимент без правки кода.
**Критерии приёмки:**
- Поддерживаются поля: id, name, brand, category, price, qty.
- Некорректные строки пропускаются с предупреждением.
- После импорта каталог доступен для поиска и заказов.
**Оценка:** 5 story points
**Приоритет:** Средний

### US-8. Экспорт отчёта по остаткам
**Как** менеджер, **я хочу** выгружать отчёт по остаткам в Markdown, **чтобы** отправлять его поставщику.
**Критерии приёмки:**
- Файл содержит таблицу: товар, бренд, остаток, статус (норма / низкий).
- Имя файла включает дату.
- Кодировка UTF-8.
**Оценка:** 3 story points
**Приоритет:** Низкий

### US-9. Скидки по промокоду
**Как** кассир, **я хочу** применять промокод при оформлении заказа, **чтобы** учитывать акции магазина.
**Критерии приёмки:**
- Промокод уменьшает итоговую сумму на заданный процент.
- Неверный промокод отклоняется с сообщением.
- В JSON заказа сохраняется применённая скидка.
**Оценка:** 5 story points
**Приоритет:** Низкий

### US-10. История заказов в консоли
**Как** менеджер, **я хочу** просматривать список оформленных заказов в консоли, **чтобы** сверять продажи за смену.
**Критерии приёмки:**
- Выводятся все заказы текущей сессии.
- Для каждого заказа показаны название, количество и сумма.
- При отсутствии заказов выводится «Заказов пока нет».
**Оценка:** 2 story points
**Приоритет:** Низкий
