# 15. Ошибки интеграции

## Ошибка 1. Несовпадение ключа `name` / `product` между cart и orders

**Что сделали.** Для проверки интеграционных тестов в `src/cart.py` в функции
`add_to_cart` намеренно заменили ключ позиции корзины `name` на `product`:

```diff
-        cart.append({"id": product_id, "name": product["name"], "size": size,
+        cart.append({"id": product_id, "product": product["name"], "size": size,
```

**Как проявилась.** Модуль `cart` сам по себе продолжает работать: товар
добавляется, `cart_total` считает сумму правильно. Но модуль `orders` при
оформлении заказа читает из позиции корзины ключ `name`:

```
python -m unittest tests.test_integration
EEE
  File "src/orders.py", line 32, in create_order
    "items": [{"id": i["id"], "name": i["name"], ...
KeyError: 'name'
Ran 3 tests ... FAILED (errors=3)
```

Все три интеграционных теста упали с `KeyError: 'name'`: модули по отдельности
корректны, но не согласованы по формату данных, который передают друг другу.

**Как исправили.** Вернули единый формат позиции корзины
`{"id", "name", "size", "price", "quantity"}` (одинаковый для `cart`, `orders`
и `analytics`) и добавили в `tests/test_cart.py` проверку ключа `name`
(`test_add_success`), чтобы такая ошибка ловилась уже модульным тестом.
После исправления: `Ran 3 tests ... OK`.

## Ошибка 2. Числовые размеры превращаются в строки после JSON

**Как проявилась.** Каталог перенесён из кода в `data/products.json`. В JSON
ключи словаря всегда строки, поэтому после `json.load` размер `40` становится
`"40"`, и вызов `add_to_cart(cart, products, 1, 40, 2)` из интеграционного теста
не находит размер:

```
Ключи размеров из json.load: ['40', '41', '42', '43']
json.load      -> (False, 'Размер 40 отсутствует у товара «Кроссовки RunFast»')
load_products  -> (True, '«Кроссовки RunFast» (размер 40) добавлен в корзину')
```

**Как исправили.** В `src/storage.py` функция `load_products` приводит
числовые ключи размеров обратно к `int` (`_size_key`), буквенные (`M`, `L`,
`183 см`) остаются строками. Добавлен модульный тест
`TestStorage.test_products_sizes_keep_type`.

## Вывод

Интеграционные ошибки возникают на стыках модулей: разные имена полей,
разные типы данных, разный формат файлов. Модульные тесты их часто не видят,
поэтому полный сценарий «каталог → корзина → заказ → файл → аналитика»
проверяется отдельно в `tests/test_integration.py`.
