# 08. Схема ветвления Git Flow — проект SportShop

## Постоянные ветки

| Ветка | Назначение | Кто сливает |
|---|---|---|
| `main` | Стабильная версия магазина, только проверенный код | release / hotfix |
| `develop` | Интеграция новых функций, текущая разработка | feature-ветки через PR |

## Временные ветки

| Шаблон | Создаётся от | Сливается в | Пример |
|---|---|---|---|
| `feature/<название>` | `develop` | `develop` | `feature/low-stock`, `feature/search-advanced` |
| `hotfix/<название>` | `main` | `main` и `develop` | `hotfix/cart-total` |

## Схема

```
main     ──●───────────────────────●──────────●──▶
            \                     / (hotfix)  /
             \     hotfix/cart-total         / (release)
develop       ●──●────●────●────●───────────●──▶
                  \  /  \  / \  /
     feature/low-stock  total-v1/v2  search-advanced
```

## Правила команды

1. В `main` и `develop` напрямую не коммитим — только слияние веток.
2. Одна feature-ветка = одна User Story (US-N), в сообщении коммита указываем номер истории.
3. Перед слиянием в `develop` создаётся Pull Request и проходит ревью.
4. После слияния временная ветка удаляется (`git branch -d`).
5. Срочные исправления — только через `hotfix/*`, слияние в `main` и в `develop`.
